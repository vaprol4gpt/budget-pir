# Правила интерфейса (30.10.2026; оформление — с 03.11.2026)

**Первоисточник оформления — дизайн-код компании `docs/design/firm-design-code/`** (`README.md`,
`tokens.json`, `firm.css`, `components/*.md`). Этот файл — правила устройства страниц программы;
цвета, шрифты, отступы, вид компонентов — только из дизайн-кода. Где расходятся — прав дизайн-код.

Короткие правила для всех страниц программы. Код каркаса — в одном месте,
`app/ui.py` (раздел «Каркас страницы»); страницы `app/app_pages/*.py` его только вызывают.
Причина появления — замечание пользователя после проверки меню 29.10: «важные кнопки
стоят рядом со второстепенными — тяжело понимать происходящее».

## 1. Меню

- Меню — **в левой боковой панели**, каждый пункт — отдельная строка, видна сразу (без
  выпадающих «ещё», вкладок, экспандеров).
- Группа **«Шаги процесса»** — по порядку работы компании: 1. Объект и ТЗ (техническое
  задание) → 2. Ведомость объёмов → 3. Максимальный бюджет → 4. Минимальный бюджет →
  5. Сводный бюджет.
- Группа **«Служебное»** — ниже, отдельным заголовком: Справочники, Версии.
- Под меню в боковой панели — контекст расчёта: объект, дата расчёта, строгий режим
  индексов, раздел изысканий, имя сметы, статусы шагов по разделам.

## 2. Каркас страницы

Сверху вниз, всегда в одном порядке:

1. **Заголовок шага** («2. Ведомость объёмов») + **одна строка «что здесь делать»**.
2. **Статус шага** (черновик / подтверждён / устарел) — сразу под заголовком.
3. **Блок ввода** — рамка (`st.container(border=True)`) с заголовком «Ввод».
4. **Блок результата** — рамка с заголовком «Результат»: таблица и итоги.
5. **Панель действий** — рамка с заголовком «Действие», внизу, отдельно от всего
   остального.

Дополнительные блоки (правка строк, утверждённая ведомость, контроль по архиву) — тоже в
рамках, между результатом и панелью действий или после неё, но никогда не внутри панели.

## 3. Кнопки

- **Одно главное действие на странице** — кнопка `type="primary"` (залитая цветом),
  всегда в панели действий:
  - «2. Ведомость объёмов» — «Подтвердить ведомость»;
  - «3. Максимальный бюджет» — «Подтвердить смету»;
  - «4. Минимальный бюджет» — «Сохранить расчёт себестоимости»;
  - «5. Сводный бюджет» — «Скачать сводный бюджет (Excel)»;
  - «1. Объект и ТЗ» — «Перейти к ведомости объёмов» («Предложить ведомость» по параметрам
    ТЗ — второстепенная, строкой «Ещё»: предложение необязательно, ТЗ объёмов не задаёт).
- Рядом с главной кнопкой (слева от неё) — **что произойдёт** при нажатии (одна строка; дизайн-код, `ActionPanel`).
- Если главное действие сейчас невозможно — кнопка **недоступна**, а рядом **причина**
  («не заполнены: Число скважин»). Нажать и получить ошибку — нельзя.
- **Второстепенные** (сохранить черновик, скачать Excel сметы, вернуться к ведомости,
  отменить правку) — обычные кнопки, в панели действий **отдельной строкой ниже** главной
  под подписью «Ещё». Кнопки внутри дополнительных блоков (правка строк; «Добавить строку»,
  «Сохранить изменения», «Удалить строку» в блоке «Свои строки (работы вне сборника)» на
  странице сметы) — тоже обычные, не `primary`.
- **Опасные** (заменяют несохранённый ввод — «Открыть смету/версию/черновик» при начатом
  расчёте) — с подтверждением: первое нажатие показывает, что будет потеряно, второе —
  выполняет.
- Служебные страницы (Справочники, Версии) главного действия не имеют.

## 4. Блоки, таблицы, сообщения

- Группировка — рамками; не больше двух уровней вложенности (рамка → экспандер).
- Таблицы — понятные заголовки колонок с единицами («Сумма, руб.», «Объём»), без
  служебных колонок там, где можно обойтись.
- Сообщения — **сверху блока**, к которому относятся, одного стиля:
  ошибка (`st.error`) — нельзя продолжать; предупреждение (`st.warning`) — можно, но
  проверьте; информация (`st.info`) — подсказка.

## 5. Числа

- Рубли — с разделителями разрядов и копейками: «28 449 810,51 руб.»
  (`app/ui.py::money_text` / `rub`). Итоги выделены жирным.
- Коэффициенты — три знака после запятой; ставки — в процентах с основанием рядом
  («НДС 22 % — 425-ФЗ…»).

## 6. Оформление (дизайн-код компании)

- Темы: светлая «Белая сталь» (основная) и тёмная «Чёрная сталь»; переключение — меню «⋮» справа сверху → System / Light / Dark (своего
  переключателя в боковой панели нет — список вопросов В-43). Кнопки Deploy нет: `[client] toolbarMode =
  "viewer"` (генерирует `app/theme/build_theme.py`).
- Все цвета, шрифты и размеры — токены `docs/design/firm-design-code/tokens.json`. Из них
  `app/theme/build_theme.py` генерирует `app/theme/firm_theme.css` (переменные обеих тем, классы
  `vs-*`, подгонка под Streamlit), `.streamlit/config.toml` (`[theme.light]`/`[theme.dark]`) и флаги
  темы для exe (`app/theme/theme_flags.json`). Сгенерированные файлы руками не правятся: правка
  токенов → `.venv/Scripts/python.exe -m app.theme.build_theme`.
- В коде страниц (`app/ui.py`, `app/app_pages/`) — ни одного цвета: только классы дизайн-кода и
  функции `app/theme` (шапка шага, бейдж, ряд итоговых цифр). Проверяет `tests/test_theme.py`.
- Компоненты: меню шагов (логотип, номер в квадрате, статус значком ✓ / ! / ×) — `StepNav`;
  шапка шага на глубоком градиенте с «Шаг N из 5» — `PageHeader` (`ui.page_header`); рамки
  «Ввод»/«Результат» — `Panel` (`ui.block`); «Действие» с изумрудной линией — `ActionPanel`
  (`ui.action_panel`, `ui.primary_action`); таблицы — `DataTable` (`ui.data_table`: заголовки
  прописными, числа справа); итоги — `Figures` (`app.theme.figures`, `st.metric`); сообщения —
  `Callout` (`st.info`/`warning`/`error`/`success` со значками i ! × ✓).
- Рамки помечаются невидимой меткой (`app.theme.mark`), а не ключом `st.container(key=…)`:
  рамки с ключом Streamlit 1.64 не убирает при переходе на другую страницу.
- Что сделано приближённо (таблицы на холсте, единица в подписи поля, кегль 16 px) — список вопросов
  В-44.
