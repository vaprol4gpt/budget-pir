# Проверка «ведомость объёмов из ТЗ» на двух объектах (03.11.2026)

Обезличенный итог сверки генератора черновика ведомости (`core/tz.py`, методы
`propose_volumes` модулей) с фактическими ведомостями эталонных листов. Подробный
построчный результат с объёмами — локально, `work/tz_check/result.md` (вне git: данные
заказчика, список вопросов В-24); скрипт сверки — `work/tz_check/check.py`. Режим «ключевые
объёмы» (инженер задаёт 3–5 главных объёмов раздела, программа достраивает остальное) —
раздел 5.

## 1. Как проверялось

- **Объекты.** Объект 1 — линейный (автодорога): ТЗ на изыскания задаёт протяжённость,
  масштаб и сечение съёмки, число искусственных сооружений (ИССО), наличие
  многолетнемёрзлых грунтов (ММГ), состав разделов. Объект 2 — площадной (карьер): ТЗ —
  только состав работ, ни одного числа (ни площади, ни масштаба); по ТЗ выбраны только
  геология и геофизика, остальные разделы сверены «как если бы были выбраны».
- **Факт** — ведомость этапа 1, которую модуль строит из ввода, воспроизводящего лист
  эталона (тот же ввод, что в `tests/test_*_etalon*.py`; у геологии — плюс правки строк
  «как в листе»). Сравниваются все строки ведомости с ненулевым объёмом.
- **Предложение** — ведомость из ввода, предложенного по параметрам ТЗ.
- **Сценарий А** — в программу введено только то, что есть в ТЗ. **Сценарий Б** — ТЗ плюс
  решения исполнителя (число скважин, средняя глубина, ширина полосы съёмки; у площадного
  объекта — площадь и масштаб), **взятые из самого листа**. Сценарий Б — не проверка
  точности (числа подсмотрены в ответе), а оценка того, сколько строк дают правила, если
  исполнитель принял эти решения.
- Статусы строки: «совпало» — отклонение не больше 1 %; «отклонение» — больше; «не
  предложено» — из ТЗ не выводится, остаётся вводом оператора. «Модуль сам» — строки,
  которые модуль даёт и без всякого ввода (программа работ, технический отчёт — по одной).
- Правила под объекты не подгонялись: они записаны до сверки (исследование
  `docs/generator_vedomosti.md`, классы связей `docs/predmetnaya_oblast.md`).

## 4. Выводы

1. Из одного ТЗ программа предлагает 12–17 % строк ведомости (с учётом строк, которые модуль
   даёт сам), главные объёмные позиции — бурение, привязка, площадь съёмки, пробы — без
   решений исполнителя не выводятся. Это совпадает с выводом исследования
   (`docs/generator_vedomosti.md` §2, §7): выигрыш — в скорости и единообразии, а не в
   «автоматическом» объёме.
2. Если исполнитель задал число скважин, глубину и ширину полосы, правила дают до 22 %
   строк точно и ещё до 9 % — с отклонением; оставшиеся ~70 % — ввод оператора
   (категории грунта, лабораторные, гидрометеорология, экологическое опробование).
3. Класс Б «термометрия = 0,5 × скважин» на обоих объектах не подтвердился (1,0 и 0) —
   вопрос к пользователю; правило в модуле не менялось (расчёт не трогали).
4. Межмодульная связь «привязка геодезии = скважины геологии» на обоих объектах не
   выполняется — остаётся оценкой с пометкой «проверьте» (В-22).

## 5. Режим «ключевые объёмы» (03.11.2026)

**Что это.** Инженер задаёт по разделу 3–5 главных объёмов — то, что из ТЗ не выводится и
что он всё равно решает сам (страница «1. Объект и ТЗ», переключатель «Как предлагать
ведомость»), а программа достраивает остальные поля ввода ведомости и показывает на
странице 2, откуда каждое значение: «ключевой объём», «правило (жёсткая связь)» с
пояснением «жёсткая связь: …», «оценка по архиву — проверьте» с пояснением «оценка по
архиву: …». Повторное предложение, как и раньше, не трогает ввод оператора; значения, оставшиеся от прошлого предложения программы и не изменённые вручную, оно обновляет (так «по ТЗ, затем по ключевым объёмам» ставит ключевые числа). Формулы
модулей не менялись: камеральные пары, привязку, программу, отчёт модули считают сами,
как прежде; режим заполняет только ввод (`core/tz.py`, `modules/*/key_volumes.py`).

**Правило отбора связей** (чтобы не подгонять под один объект): связь считается **жёсткой**,
только если она выполняется на **обоих** объектах **и** имеет физический смысл (одна проба —
один анализ; план чертят по съёмке; промер — на каждом створе; камеральная обработка — тех
же пунктов). Связь, которая есть только на одном объекте, или совпадение чисел без
физического смысла — **оценка по архиву** с пометкой «проверьте».

- Жёсткие (новые): крепление скважин = метраж с гидронаблюдениями; высотная сеть, камеральная обработка плановой сети, знаки = пунктам плановой сети;
  план = съёмке; анализы воды, донных отложений, гамма-спектрометрия = своим пробам; промеры
  = створам; графики и кривая расходов = измерениям расхода; уклон водосбора = площади
  водосбора = водосборам; расчёты стока «первый водосбор» = 1, «последующие» = водосборов − 1.
  **Производное от оценки — тоже оценка**: если исходное число оценено, связанное с ним по
  жёсткой связи помечается «оценка по архиву» (коррозия к бетону = к стали, а число проб к стали —
  оценка; графики и кривая расходов = измерениям расхода, если те оценены 2 на водоток).
- Оценки по архиву: глинистые + песчаные = монолитам дисперсных (сумма — на обоих объектах,
  доля глинистых 75–80 % — середина); коррозия = пробам воды и тяжёлые металлы/нефтепродукты
  в почвах = пробам на радионуклиды (совпало на обоих, физической связи нет); донные
  отложения = пробам воды; база геодезии — 2 мес.; рекогносцировка реки и морфостворы —
  1 км на водоток, фотоработы — 10 на водоток, ГВВ = измерениям расхода; у геофизики всё
  достроенное (лист — у одного объекта): камеральная обработка электроразведки при ВЭЗ и
  технический отчёт при полевых работах (отчёт один на раздел у всех разделов обоих объектов,
  но для геофизики это не проверено).

**Как проверялось.** Тот же скрипт сверки, расширенный (локально,
`work/briefs/scripts_dd_dovodka/tz_check/check_keys.py`; результат с объёмами — рядом, вне
git). Сценарий **В** = ТЗ + решения исполнителя (сценарий Б) + ключевые объёмы, **взятые из
самого листа** — это честно: ключевые объёмы и есть решения исполнителя, которые он принимает
до сметы; но это in-sample, как и сценарий Б. Для разбора вклада — две промежуточные
ступени: **В0** — только сами ключевые объёмы (плюс то, что модули считали и раньше), **В1** —
В0 + жёсткие связи без оценок архива. Две доли: «строка предложена» (в черновике есть строка с
ненулевым объёмом) и «объём совпал» (отклонение не больше 1 %). Число ключевых объёмов,
заданных из листа: 20 значений у объекта 1, 18 — у объекта 2.
