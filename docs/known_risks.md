# Известные риски проекта

Единый реестр рисков. Сжат 05.11.2026 (аудит): закрытые пункты — одной строкой в конце,
пересекающиеся объединены; прежняя редакция — `git show 22098e8:docs/known_risks.md`. Вопросы к
людям — список вопросов (номера В-NN); правила параметров — `data/pravila_parametrov.json`.

Критичность: **высокая** — влияет на выдаваемые суммы или ломает сценарий; **средняя** — сужает
охват или удобство; **низкая** — наблюдение на будущее.

## 1. Главные риски (по аудиту 05.11.2026, внутренняя проверка)

Найденные аудитом ошибки (О-1…О-9) и порядок их исправления — в план работ, этапы А–Д;
здесь — постоянные риски.

- **Репозиторий `budget_pir` на GitHub и `.git` этой папки хранят данные заказчика** — высокая, пока
  перенос не сделан и старый не удалён (В-57, отложено пользователем 05.11). По хэшу скачиваются коммиты
  с ними; в него никого не приглашать. Дерево текущей ветки очищено, хук перед отправкой проверяет
  каждый коммит. Хук видит только слова из своих списков и работает лишь на ПК, где эти списки есть.
- **Смета нового объекта зависит от параметров, которых программа не знает** — высокая. Каждый
  раздел воспроизводит свой эталонный лист ± 0,1 %, но при коэффициентах, пунктах расценок и
  ставках начислений, взятых из готовой сметы. Без неё значения по умолчанию — допущения
  (справочник правил: статусы `assumption` и `input`). Закрывается ответами отделов (опросник),
  а не кодом.
- **Минимальный бюджет не калиброван** — высокая для любого использования коэффициента снижения.
  Нормы выработки — по одному объекту 2016 г.; ставки локального слоя — ценовые (Форма 2.2), не
  себестоимостные; факта закрытого объекта нет. На малом объекте минимум больше максимума. В-12,
  В-31, В-55.
- **Индексы пересчёта — только III кв. 2026** — средняя. С 01.10.2026 расчёт «на сегодня» берёт
  индекс прошлого квартала с предупреждением (или не даёт итога в строгом режиме). Способ внесения
  без нового эталона готов (`data/indeksy.json`, с 05.11.2026), значений нет: нужно письмо Минстроя
  от сметного отдела (В-6, В-7).
- **Эталоны — два объекта одного заказчика и одного шаблона компании** — средняя. Правила, выведенные
  из них (связи ключевых объёмов, типовые профили, схемы начислений), на третьем объекте не
  проверялись (В-54).

## 2. Данные и нормативка (нужен бумажный сборник или ответ специалиста)

- **Геология.** Справочник не покрывает 13 строк листа «1.2.1_ИГИ» (основание без номера таблицы
  или на два пункта) — средняя; три пары позиций с одинаковым кодом и разной ценой исключены
  решением пользователя 18.09.2026 (конфликтующие ключи т.9 п.3, т.57 п.2, т.101 п.5 разведены
  30.10). Источник 73 позиций без названия сборника принят как СБЦ-99 (В-10) — низкая. Расход
  бурового инструмента по категориям буримости не реализован: норматива нет (встреченные
  коэффициенты — черновая оценка по одному объекту), вопрос к нач. ОИГ — средняя. Коэффициенты
  листа 1,25 / 0,7 / 1,2 — параметры по умолчанию 1 (В-47).
- **Внутренний транспорт СБЦ-99 т.4.** Диапазон расстояний известен только у п.4 (10–15 км) и п.5
  (20–25 км); вне их модуль берёт пункт своего эталона с предупреждением, у геологии и экологии
  он разный; ставки 11,25 % из листов карьеров в справочнике нет (В-15, В-40) — средняя.
- **Геофизика.** Коэффициенты ВЭЗ, МПВ и камеральных — параметры по умолчанию 1; основания по
  бумажному СЦиР-1982 не сверены; оргликвидация листа — формула с «0,025 %» (В-26, В-37). Влияние
  на итог раздела ≈ 15 % — средняя.
- **Геодезия.** Цены съёмки и плана есть для 1:500, 1:1000, 1:2000; для 1:5000 и 1:10000 —
  «цена не найдена». Пункт т.82 базы экспедиции (меняет итог раздела на четверть), пункт т.48
  привязки, знаки в базе транспорта, коэффициент трассы — ввод без правила (В-36, В-53) — средняя.
- **Экология.** Две позиции без цены СБЦ-99 (физические факторы; исходные данные) и два вида проб
  без цены — строки строятся с ценой 0 и говорящим основанием. Коэффициент камеральной строки
  маршрутных наблюдений и пункт Т80 п.13/п.14 — ввод оператора; тяжёлые металлы в донных — ×1 как в
  формулах листов (в расчёте листа написано ×7); объём камеральной строки = полевой — допущение
  нового шаблона (В-38) — средняя.
- **Гидрометеорология.** Без правила (ввод оператора): сумма программы т.53, ставки внутреннего
  (т.4 §5) и внешнего (СБЦ-97 т.5 §6) транспорта, районные коэффициенты; ×1,4 неблагоприятного
  периода — число из шаблона компании. Категории сложности только II и III; цены кат. II пяти позиций —
  константы `HYDROMET_CATEGORY_II_SUPPLEMENT` (сметы сторонних клиентов сознательно не копируются).
  База техотчёта — формула обоих эталонов (на других листах шаблона встречались иные варианты).
  Не реализованы редкие позиции (материалы УГМС, научное сопровождение, страховой фонд, вариант
  «расстояние < 25 км» с × 0,85). Подробно — `docs/hydromet_diagnostics.md`, разделы 7–8 (В-35) —
  средняя.
- **Мобилизация / демобилизация** — только показ в сводной (нормы нет, В-27) — низкая.
- **НДС на даты до 01.01.2019** не внесён: ставка «не найдена», итог без НДС — низкая.
- **Старые версии экологии с правкой цены пробы** (до 25.10.2026): коэффициент вида пробы может
  примениться дважды; оператор видит «расчёт отличается от снимка», раздел не идёт в бюджет до
  переподтверждения — низкая.

## 3. Архитектура и масштабируемость

- **Каждый новый сборник — свой парсер в `data/build_references.py`** (формат ячейки цены разный
  у всех источников); `main()` копирует блок оркестрации на каждый источник — при 6+ источниках
  обобщить в цикл — средняя.
- **`EstimateLine.id` и `module.code` — конвенции, не проверяемые каркасом** — низкая; станет
  заметной, если появится общий экспорт строк нескольких разделов.
- **Одна смета на раздел в бюджете**: несколько смет одного вида (три карьера) — только суммой
  объёмов (В-53) — средняя.
- **Сводный бюджет собирается из сессий разделов текущей вкладки**; снижение цены и целевая цена
  после перезапуска из базы не восстанавливаются (В-46, В-50) — средняя.
- **`ReferenceBook` открывает соединение SQLite на каждый вызов; таблица `edits` без индекса по
  `smeta_id`** — низкая при текущих объёмах.
- **`effective_estimate` использует `hasattr` как признак поля `EstimateLine`** — низкая.
- **Парсер ИГМИ читает кэш внешних книг через закрытый атрибут openpyxl** — низкая; при обновлении
  openpyxl проверить `tests/test_hydromet_references.py`.
- **Геофизика и геодезия строят строки явными блоками кода, не таблицей** — низкая.
- **Выбор раздела — `st.radio` в боковой панели (`app/ui.py`), пять пунктов**; при 6–8 разделах
  заменить на `st.selectbox` (остальная логика от вида виджета не зависит) — низкая.
- **Модель «трудозатраты» (методика 707/пр, проектные разделы) на контракте `BudgetModule` не
  проверена** — средняя для будущих разделов.
- **Приближения дизайн-кода** (таблицы на холсте, кегль, шрифты из сети) — В-44 — низкая.

## 5. Эксплуатация

- **`data/smety.sqlite` вне git, бэкапа нет** — средняя с началом реальной эксплуатации.
- **Старый exe на смете со «своей строкой»** откроет её с ошибкой формата — обновлять exe на всех
  ПК одновременно (В-46) — низкая.
- **exe не проверялся на чужом ПК** (только в изолированной папке на ПК разработки); нет иконки;

  GitHub сверять не с чем (В-51) — средняя.
