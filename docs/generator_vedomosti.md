## 1. Термины

- **ТЗ** — техническое задание заказчика на инженерные изыскания.
- **Ведомость объёмов работ** — перечень работ с объёмами в натуральных единицах (метры
  бурения, число скважин, гектары съёмки, точки, пробы); этап 1 каждого модуля программы
  (`core/stages.py`; описание проекта, «Архитектура»).
- **СП** — свод правил (нормативный документ по изысканиям, например СП 47.13330
  «Инженерные изыскания для строительства»); по СП исполнитель выбирает шаг и глубину
  выработок.
- **Выработка / скважина** — точка бурения для изучения грунтов; **п.м.** — погонный метр
  бурения.
- **ММГ** — многолетнемёрзлые грунты (вечная мерзлота).
- **ИССО** — искусственные сооружения на дороге (мосты, трубы).
- **Генератор ведомости** — функция, которая по параметрам ТЗ **предлагает** черновик
  ведомости; окончательные объёмы утверждает оператор.

## 2. Главный факт: ТЗ объёмов не задаёт

По разбору ТЗ на изыскания реального заказа (`docs/istochniki/README.md`, вывод сверки;
подробный разбор — локально `work/istochniki/02_tz_kp.md`, §1.4–1.5):

- ТЗ **не содержит** объёмов работ: ни метража бурения, ни числа выработок, ни площади
  съёмки, ни числа проб;
- ТЗ даёт только **«каркасные» параметры**: вид и протяжённость объекта, число и размер
  ИССО, масштаб и сечение рельефа съёмки, наличие ММГ и сейсмичности, район работ,
  перечень видов работ с пометками «требуется / при необходимости», ссылки на СП;
- ключевые количественные решения — ширина полосы съёмки, шаг и глубина выработок,
  распределение метража по категориям грунта, число проб, длина участков промеров,
  расстояние до базы, категория сложности — **в ТЗ не заданы**: их принимает исполнитель
  по СП и своей практике, и нигде в документах компании эти правила не записаны
  (список вопросов В-22).

Вывод: генератор может быть только **предлагающим** — черновик с объяснением, откуда
взято каждое число, плюс обязательная проверка оператором. Полностью автоматическая
ведомость из ТЗ невозможна без правил компании. Это согласуется с решением сделать
ведомость отдельным подтверждаемым этапом (`docs/multistage_design.md`, раздел 7).

## 3. Четыре вида связей «исходные данные → объём»

Связи различаются по надёжности. От вида связи зависит, что программа может сделать
сама, а что — только предложить.

| Вид связи | Что значит | Надёжность | Что делает программа | Пример (геология) |
|---|---|---|---|---|
| **Жёсткая** (класс А) | объём однозначно следует из другой величины | проверено на 11 сметах 5 объектов | считает сама; правка — только осознанно | привязка = число скважин |
| **Устойчивый коэффициент** (класс Б) | объём = коэффициент × величина, коэффициент одинаков во всех сметах | то же | считает сама, показывает коэффициент | термометрия = 0,5 × число скважин |
| **Статистический диапазон** (класс В) | есть только типовой диапазон «на скважину», меняется от объекта к объекту | диапазон усреднён по нескольким объектам | предлагает середину диапазона с пометкой «типовой профиль, требует проверки» | монолиты дисперсных грунтов 1,39–3,57 на скважину |
| **Решение исполнителя / правило СП** | число выбирается по нормативу или практике, из данных не выводится | — | не угадывает: поле ввода оператора; может подсказать, если правило получено от компании | число скважин, метраж по категориям, ширина полосы съёмки |

Источник классов А/Б/В — `docs/predmetnaya_oblast.md` (11 реальных смет, 5 объектов);
реализация в коде — `modules/geology/module.py` (`TERMOMETRIYA_RATE_PER_HOLE = 0.5`,
`MONOLITY_*_PER_HOLE` — середины диапазонов, предупреждения `check()` для профиля).

Отдельная группа — **позиции, которые не коррелируют** с исходными данными или выведены
из одной сметы: большинство лабораторных определений (`docs/predmetnaya_oblast.md`,
раздел «Лабораторные позиции»). Их генератор не предлагает, кроме трёх позиций с
точным совпадением 1:1 и физическим смыслом (каждый образец получает своё определение),
которые уже реализованы с отдельным, более осторожным предупреждением.

## 4. Цепочка вывода по разделам изысканий

### 4.1. Геология (ИГИ) — связи изучены лучше всего

Таблица 4.1 — Позиции ведомости геологии и источник объёма

| Позиция ведомости | Как получается объём | Вид связи | Кто задаёт |
|---|---|---|---|
| Число скважин | протяжённость трассы / шаг выработок по СП + дополнительные выработки на ИССО | правило СП + решение исполнителя | оператор; ПРЕДПОЛАГАЮ: программа может предложить, если получит от компании шаг по СП для вида объекта |
| Метраж бурения по категориям грунта | число скважин × глубина, распределение по категориям буримости | решение исполнителя (геология конкретного участка) | оператор (группа строк «категория + метраж», `Field.type="group"`) |
| Плановая и высотная привязка скважин (табл. 93, п. 3) | = число скважин | жёсткая (А) | программа |
| Камеральная обработка материалов бурения (табл. 82, п. 1) | = метраж бурения, п.м. | жёсткая (А) | программа |
| Составление программы работ (табл. 81, п. 2) | = 1 | жёсткая (А) | программа |
| Составление технического отчёта (табл. 87, п. 2) | = 1 (цена — доля 0,22 от камеральных строк) | жёсткая (А) | программа |
| Термометрия в скважинах (табл. 40, п. 3) | = 0,5 × число скважин | устойчивый коэффициент (Б) | программа |
| Монолиты дисперсных грунтов (табл. 57, п. 1) | 1,39–3,57 на скважину | диапазон (В) | программа предлагает середину, оператор проверяет |
| Монолиты скальных грунтов (табл. 57, п. 2) | 0,455–1,94 на скважину | диапазон (В) | то же |
| Пробы воды (табл. 60, п. 2) | 0,125–0,214 на скважину | диапазон (В) | то же |
| Суммарная влажность; стандартный анализ воды; физ.-мех. свойства скальных грунтов | = числу монолитов дисперсных / проб воды / монолитов скальных | 1:1, выведено из одной сметы | программа, с осторожным предупреждением |
| Прочие лабораторные (глинистые/песчаные, коррозия, оптимальная влажность) | связи нет или пропорция одного объекта | не коррелируют | оператор |

Источник: `docs/predmetnaya_oblast.md`; номера таблиц — СБЦ-99.

**Проверка на здравый смысл** (не формула, а контроль): камеральная обработка / привязка
= средняя глубина скважины, обычно 4,7–15,4 м (`docs/predmetnaya_oblast.md`, класс А).
Генератор должен показывать это отношение и предупреждать при выходе за границы.

ПРЕДПОЛАГАЮ: наличие ММГ в ТЗ — признак того, что термометрия нужна (наблюдения за
температурой грунтов выполняются на мерзлоте); в 11 сметах коэффициент 0,5 устойчив, но
были ли среди них объекты без мерзлоты — в `docs/predmetnaya_oblast.md` не сказано.
Поэтому флаг ММГ из ТЗ стоит использовать как включатель строки, а коэффициент — как
есть.

## 6. Эскиз будущей страницы: «Объект и ТЗ → предложенная ведомость → правка оператором»

Сейчас на странице «1. Объект и ТЗ» — данные объекта и заготовка «Параметры
технического задания — планируется» (`app/app_pages/p1_obekt.py`); объёмы вводятся
вручную на странице «2. Ведомость объёмов» (описание проекта, таблица меню).

Предлагаемая схема (ПРЕДПОЛАГАЮ — проектное решение, не согласовано):

```
 Страница «1. Объект и ТЗ»                     Страница «2. Ведомость объёмов» (модуль)
 ┌───────────────────────────────┐             ┌────────────────────────────────────────────┐
 │ Данные объекта (как сейчас)   │             │ Предложенная ведомость (черновик)          │
 │ Параметры ТЗ:                 │             │  строка | объём | откуда              | ✎   │
 │  вид объекта, протяжённость,  │  «Предложить│  привязка  | = скважин   | жёсткая (А) |     │
 │  ИССО, масштаб/сечение,       │  ведомость» │  термометр.| 0,5×скважин | коэф. (Б)   |     │
 │  ММГ, сейсмичность, район,    │ ──────────► │  монолиты  | середина    | диапазон (В)| ⚠   │
 │  флаги видов работ            │             │  скважины  | —           | ввод        | ✎!  │
 │ Решения исполнителя:          │             │ Предупреждения check(): профиль, глубина   │
 │  шаг/глубина выработок,       │             │ Правка оператора (журнал правок)           │
 │  ширина полосы, категории     │             │ [Подтвердить ведомость] → версия           │
 └───────────────────────────────┘             └────────────────────────────────────────────┘
          хранится с версией                       дальше — «3. Максимальный бюджет»
```

Принципы:

1. **Каждое предложенное число — с происхождением**: «из ТЗ», «жёсткая связь»,
   «коэффициент», «типовой диапазон», «правило компании (источник)», «ввод оператора».
   Без происхождения оператор не может проверить черновик.
2. **Ничего не подтверждается автоматически.** Предложение — это заполненный черновик
   этапа 1; подтверждение ведомости остаётся действием оператора (как сейчас,
   `core/stages.py`).
3. **Правка — через существующий слой правок** (`core/overrides.py`, свой журнал на
   этап): видно, какие значения оператор изменил относительно предложения.
4. **Параметры ТЗ хранятся с версией** — как данные объекта (`core/object_data.py`), чтобы
   версия ведомости была воспроизводима.
5. **Повторное «Предложить» не затирает правки молча** — ПРЕДПОЛАГАЮ: показывать разницу
   и спрашивать.
6. ПРЕДПОЛАГАЮ по архитектуре: у модуля появляется необязательный метод «предложить
   объёмы по параметрам ТЗ»; модуль без него работает как сейчас (так же расширялся
   контракт `Field` — необязательными атрибутами, описание проекта, «Архитектура»). Ядро `core/`
   знает только общий набор параметров ТЗ.

## 7. Риски

- **Правил компании нет** (список вопросов В-22): без них генератор заполнит только жёсткие и
  статистические позиции, а главные драйверы (скважины, метраж, площадь) останутся
  вводом оператора. Выигрыш — в скорости и единообразии, а не в «автоматическом» объёме.
- **Эффект якоря**: оператор может принять предложенную середину диапазона без проверки.
  Защита — пометка «типовой профиль», показ диапазона, предупреждения `check()`.
- **Узкая база статистики**: классы А/Б/В — 11 смет 5 объектов и только для геологии;
  лабораторные — одна смета (`docs/predmetnaya_oblast.md`).
- **Расхождения внутри одного комплекта документов** (например, разное число точек
  привязки у геодезии и геологии; список вопросов В-22) — межмодульные связи пока только как
  подсказка, не как формула.

## 8. Что нужно от пользователя для реализации

1. Правила компании «ТЗ → объёмы»: ширина полосы съёмки по виду объекта, шаг и глубина
